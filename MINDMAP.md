## Directory Architecture

```
shopify/                              (outer repo — thin wrapper, not a submodule setup)
└── my_shop_project/                  (nested repo, own remote → GitHub)
    ├── backend/                      Express 5 + Mongoose 8 + Socket.IO API
    │   ├── server.js                 App bootstrap: CORS, JSON, io injection, route mounting
    │   ├── db.js                     Mongoose connection
    │   ├── models/                   Order, Product, Review, User (4 collections total)
    │   ├── routes/                   8 route files → thin, map path to controller fn
    │   ├── controllers/              8 controllers — all business logic lives here
    │   └── middleware/
    │       ├── authMiddleware.js     JWT verify → req.user = { id, role }
    │       └── roleMiddleware.js     authorizeRole(...roles) gate
    └── frontend/                     CRA (react-scripts 5) + Tailwind + React Router 7
        └── src/
            ├── App.js                Router shell + Layout (navbar, socket listeners)
            ├── contexts/
            │   └── AuthContext.js    token/role/name/user + favorites, axios calls
            ├── OrderContext.js       just lastTrackedOrderId (tiny, single-purpose)
            ├── ProtectedRoute.js     route guard — reads localStorage directly (NOT context)
            ├── config.js             API_URL from REACT_APP_API_URL
            ├── Toast.js              ToastProvider (app-wide)
            ├── components/           NotificationPanel, ReviewModal, StarRating
            └── *Page.js / *.js       ~18 flat top-level page/feature components
```

## Data Model (Mongoose)

```
User  ──┬── role: 'customer' | 'shopkeeper'  (single collection, dual-purpose schema)
        ├── customer fields: favorites[→User], savedAddresses[], recentSearches[]
        └── shopkeeper fields: shopName, city, pincode, shopImage, averageRating

Product ── shop: →User (required)            [text index: name/description/category]
Order   ── shop: →User, customer: →User?     [denormalizes shopName, customerName]
Review  ── customer: →User, shop: →User, order: →Order?  [unique per (customer, shop)]
```

Shops and customers are the **same `User` collection**, distinguished only by `role`. Any change
to `User` (e.g. adding a shopkeeper-only field) touches both personas.

## Real-time (Socket.IO) Flow

```
server.js: io created alongside http server, attached to every req as req.io
Client (App.js): ONE global socket connection for the whole app lifetime
  → emits joinShopRoom(shopId) / joinCustomerRoom(customerId) based on role
  → listens: `customerNotification:${userId}`, `newOrder`

orderController.updateOrder / paymentController (verify/place order) emit:
  io.emit('newOrder', ...)                        ⚠ broadcast to ALL sockets, not room-scoped
  io.to(`shop:${shopId}`).emit('newOrder', ...)    room-scoped (redundant with line above)
  io.emit(`orderUpdate:${orderId}`, ...)
  io.emit(`customerNotification:${customerId}`, ...) ⚠ global emit keyed by string event name
                                                       instead of room targeting
```

## State & Storage Boundaries

```
localStorage:  token, role, name, savedCustomer{Name,Contact,Address}
               ⚠ read independently in 3 places: AuthContext, ProtectedRoute, CheckoutForm
               (no single source of truth — see risk #3 below)

React Context: AuthProvider (auth/user/favorites) wraps OrderProvider wraps ToastProvider
               → CheckoutForm and ProtectedRoute bypass AuthContext and hit localStorage/
                 jwt-decode directly instead of useAuth()

Server state:  no caching layer — every read hits MongoDB directly via Mongoose
```

## Structural Review: Risk Areas & Touchpoints

| # | Area | Issue | Why it matters |
|---|---|---|---|
| 1 | Secrets in git history | `.env` committed + pushed (see top) | Immediate credential exposure |
| 2 | `paymentController.placeOrder` / `orderController.createOrder` | `totalAmount` and `items[].price` come straight from the client request body and are saved as-is; nothing recomputes the total from `Product.price` in the DB | A customer can submit any `totalAmount`/price for a COD or (pre-verification) order — price-tampering gap. Razorpay's *charged* amount is server-trusted, but the *order record* total isn't cross-checked against it before save |
| 3 | Auth state duplication | `AuthContext`, `ProtectedRoute.js`, and `CheckoutForm.js` each independently read `localStorage`/decode the JWT instead of going through `useAuth()` | Three sources of truth for "who is logged in" — switching auth storage (e.g. httpOnly cookies) means hunting down every direct `localStorage.getItem('token')` call |
| 4 | Socket broadcasting | Several `io.emit(...)` calls broadcast to **every connected client** rather than only the relevant room, even though rooms (`shop:${id}`, `customer:${id}`) already exist | Leaks order events across tenants; won't scale; notification logic relies on filtering dynamic event-name strings instead of a stable payload shape |
| 5 | `User` model dual-purpose | Single collection for shopkeeper + customer via `role` enum, no discriminator/subschema | New shopkeeper-only/customer-only fields risk leaking into the other persona's `/api/auth/me` response; no schema-level enforcement of which fields belong to which role |
| 6 | Denormalized fields | `productCount`/`averageRating` on `User`, `shopName`/`customerName` on `Order` copied at write time, no visible sync job | Renaming a shop or editing a product won't retroactively update historical records unless every write path remembers to update them |
| 7 | Flat frontend `src/` | 18+ page components at top level, no `pages/`/`features/`/`api/` split; only 3 shared `components/` | Fine at current size; will get noisy as more pages are added |
| 8 | CORS allowlist | Hardcoded to `localhost:3000` + one Render URL in `server.js` | New deploy targets require editing `server.js` directly |

## Where new work plugs in cleanly

- **New API resource** (coupons, cart persistence, etc.): `models/X.js` → `controllers/xController.js`
  → `routes/x.js`, mounted in `server.js` next to the existing 8. Pattern is consistent.
- **New role/permission**: `roleMiddleware.js`'s `authorizeRole(...roles)` already generalizes past
  two roles; friction point is the `User` schema (#5).
- **New real-time event**: alongside the existing `updateOrder` handler in `orderController.js` —
  fix the broadcast-vs-room issue (#4) at the same time rather than propagate it.
- **New frontend page**: add to `src/`, add a `<Route>` in `App.js`, wrap in `<ProtectedRoute>` if
  needed — route auth checks through `useAuth()` rather than `localStorage` directly (#3).
